Question 10: AGI and superintelligence

Which choice correctly describes both AGI and superintelligence?

a. AGI: AI whose weights are published. Superintelligence: the most capable closed model.

Wrong. An AI whose weights are published is an open-weight model, and a model that only its maker runs is a closed model. These terms describe how a model is shared, not how capable it is compared with humans.

b. AGI: AI that improves its own code. Superintelligence: AI that uses tools such as web search.

Wrong. AI that improves its own code is closer to recursive self-improvement (RSI), and using tools such as web search is what an agent does. Neither describes AGI or superintelligence.

c. AGI: very good at one task, such as chess. Superintelligence: good at many tasks.

Wrong. An AI that is very good at one task, such as chess, is narrow AI, not AGI. And being good at many tasks is not enough for superintelligence: it must far surpass the best humans.

d. AGI: matches humans at most thinking tasks. Superintelligence: far beyond the best humans. (correct answer)

Correct. AGI is AI that matches humans at almost all thinking tasks. Superintelligence is AI far better than the best humans in nearly every field. Both are hypothetical today.

In the other versions, this was question 18 in Version B (correct answer: b) and question 27 in Version C (correct answer: a). The choices are in a different order in each version.

Background

These terms describe how capable an AI is compared with humans, and how many kinds of tasks it can do.

Term Meaning Exists today?
Narrow AI built for one task, such as a chess engine, a spam filter or a fraud detector; it can be superhuman at that task and useless outside it yes
AGI (artificial general intelligence) AI that could learn and do essentially any thinking task a human can, and carry skills over to new problems no, hypothetical
Superintelligence AI far better than the best humans in nearly every field no, hypothetical

Today’s LLMs sit between narrow AI and AGI. One model can write an essay, fix code and read a chart, so it is far more general than narrow AI. But its abilities are uneven (“jagged”): it can help with a hard math problem and still miscount the letters in a word. There is no agreed definition or test for AGI, and people disagree about whether and when it will arrive.

Other terms describe different things, not levels of intelligence:

  • Open-weight and closed describe how a model is shared: published weights, or use only through the maker’s app or API.
  • Agent describes how a model is used: an LLM plus tools plus a loop.
  • Recursive self-improvement (RSI) describes a process: AI builds the next, more capable AI, again and again. It is dangerous because people may no longer understand what the resulting AI can do.

Question 11: Why AI labs focus on coding

Why have AI companies such as Anthropic and Google worked so hard to make their models good at coding?

a. New laws require AI models to pass a coding test before release.

Wrong. No law requires AI models to pass a coding test before release. The focus on coding comes from what code lets an AI do.

b. Most of their paying customers are professional programmers.

Wrong. Coding tools do sell well, but sales are not the main reason. The deeper reason is that coding ability lets an AI extend everything else it can do.

c. Code is shorter than English, so training on code costs less.

Wrong. The focus on coding is not about saving money on training. Models are trained on huge amounts of text of all kinds. Labs focus on coding because of what programs can do, not because code is short.

d. A model that writes programs can do anything a program can do. (correct answer)

Correct. If an AI can write a program to do something, it can do anything a program can do. This lets the AI extend its own capabilities, and it could eventually lead to recursive self-improvement (RSI).

In the other versions, this was question 39 in Version B (correct answer: c) and question 5 in Version C (correct answer: c). The choices are in a different order in each version.

Background

An LLM by itself predicts the next token. It answers from patterns it learned in training. That is non-deterministic: the answer depends on probability, so it is not always the same, and not always right.

A classic program is deterministic: it follows fixed rules and gives the same result every time. So for exact tasks, a program does better than the model’s guess.

Two examples from earlier models:

  • Adding two very large numbers. The exact sum probably never appeared in the training data, so the model often guessed wrong. When asked to write a Python program that adds the numbers, it got the right answer.
  • Counting the i’s in “mississippi”. The model relied on its memory from training and got it wrong. A short program counted correctly.

The general idea: a model that can write and run programs can do anything a program can do. Programs can do exact arithmetic, read files, analyze data, work with websites, and much more. So coding ability is not just one more skill. It lets an AI extend its capabilities and do things that it could not do before.

This is why model builders, especially Anthropic and Google, work so hard on coding. It also leads to a bigger idea. AI models are themselves built with programs, so an AI that codes well can help build the next AI. Taken far enough, this is recursive self-improvement (RSI): AI builds the next, more capable AI, again and again.

Newer models make fewer of these mistakes. They have more training, and their harnesses often run code behind the scenes for them.

Question 12: Hidden contents of the context window

Which of these takes up space in Claude Code’s context window, even though you may not see it on the screen?

a. The text of every file in your project.

Wrong. Only the files that Claude has opened are in the context window, not every file in the project. Each file that Claude reads does take space, even though you see only one line such as Read auth.ts.

b. Your usage numbers, which Claude checks before each reply.

Wrong. Your usage is tracked on Anthropic’s side and shown by /usage. Claude does not read your usage numbers before each reply, and they are not part of the conversation.

c. The model’s thinking, as it works through different possibilities. (correct answer)

Correct. A reasoning (thinking) model writes out intermediate steps before its final answer. This thinking is part of the model’s output, so it goes into the context window even if you do not see it. Higher effort means more thinking and more tokens.

d. The training data that the model read while it was being built.

Wrong. Training data is not in the context window. What the model learned in training is stored in its weights, which are a different kind of memory.

e. Your chats with Claude in other projects on the same computer.

Wrong. Each session has its own context window. Chats in other projects are not in it, and a new chat starts without the earlier ones.

In the other versions, this was question 23 in Version B (correct answer: b) and question 6 in Version C (correct answer: a). The choices are in a different order in each version.

Background

The context window is the model’s working memory for one session. It is the maximum amount of text, measured in tokens, that the model can consider at once. Everything in it uses that space, whether you see it on the screen or not.

What fills the context window in Claude Code:

Part Shown on the screen?
Claude Code’s instructions (the system prompt) no
CLAUDE.md, auto memory, skill descriptions, MCP tool names no
your messages and Claude’s replies yes
every file Claude reads and every command’s output usually only one line, such as Read auth.ts
the model’s thinking usually not in full

A reasoning model (or “thinking” model) writes out intermediate steps, called thinking, before its final answer. Thinking helps on multi-step problems such as planning and debugging. But thinking is output, so it takes space in the context window, and thinking tokens are billed like other output tokens. The effort setting (low, medium, high, xhigh, max) controls how much the model thinks: higher effort means more thinking and more tokens.

What is not in the context window:

  • the training data (the model’s long-term knowledge is stored in its weights),
  • files that Claude has not opened,
  • other sessions and other projects,
  • your usage numbers.

Run /context in Claude Code to see a colored grid of what is using space now.

Question 13: What the context window holds

Which of the following are in Claude Code’s context window for a particular chat?

a. All the text that the model read while it was being trained.

Wrong. This confuses the context window with training. What the model read in training is stored in its weights, not in the context window of a chat.

b. Only the last message you typed, and nothing that came before it.

Wrong. Each time you send a message, the whole conversation so far is sent to the model again. The model needs the earlier messages to follow the conversation.

c. Only the messages from you and Claude that appear on the screen.

Wrong. This leaves out the text that you do not see, most importantly the system prompt: hidden instructions from the company that runs the AI.

d. Your messages, Claude’s replies, and a hidden system prompt. (correct answer)

Correct. The context window holds all the text of the chat, typed by you or by the AI, plus the hidden system prompt. In Claude Code it can hold more, such as CLAUDE.md, skill descriptions and the files Claude reads, but this choice names the main parts correctly.

e. Every chat you have ever had with Claude Code, from the first one.

Wrong. A new chat starts with an empty conversation. Earlier chats are not in its context window unless you go back to one, for example with /resume.

In the other versions, this was question 34 in Version B (correct answer: d) and question 13 in Version C (correct answer: b). The choices are in a different order in each version.

Background

An LLM has two very different kinds of memory.

  • Long-term memory is what the model learned in training. It is stored in the model’s weights and stops at the knowledge cutoff, the date when its training data ends. It does not change while you chat.
  • Working memory is the context window: the text that the model can consider for the current request. It is measured in tokens.

The model remembers nothing between requests. Each time you send a message, the app sends the whole conversation so far to the model again. So the context window of a chat holds:

  • your messages,
  • the AI’s replies,
  • the system prompt: hidden instructions from the company that runs the AI. They tell the model how to behave, for example which tools it has and what it must not do. Some companies’ system prompts have been made public.

In Claude Code, the context window can also hold CLAUDE.md, auto memory, skill descriptions, MCP tool names, every file Claude reads, every command’s output, and the model’s thinking.

What is not in it:

  • the training data,
  • other chats. A new chat starts empty, unless an app’s memory feature adds saved notes.

Useful commands in Claude Code:

  • /clear starts a new conversation with an empty context (CLAUDE.md, the system prompt and the skill descriptions are still loaded).
  • /resume shows earlier conversations that you can go back to.
  • /context shows what is using space.

Question 14: Context rot in long sessions

After a very long Claude Code session, Claude starts ignoring a decision that you made about halfway through. What is the most likely cause?

a. The model’s training cutoff date passed during the session.

Wrong. The training cutoff is the fixed date when the model’s training data ends. It cannot pass during a session, and it has nothing to do with the messages in your chat.

b. The context window has become very full. (correct answer)

Correct. This is context rot. As the context window fills up, the model gets worse at using what is in it. It tends to miss information in the middle of a long conversation most often.

c. You hit your weekly limit, so Claude switched to a weaker model.

Wrong. When you hit a usage limit, you are blocked until the limit resets, unless you upgrade or use usage credits. Claude does not switch to a weaker model.

d. The temperature slowly rose during the long session.

Wrong. Temperature is a setting that controls how random the choice of the next token is. The app sets it, and it does not rise during a session.

e. The prompt cache expired while the session was running.

Wrong. When the prompt cache expires, the next reply costs more, because the server must process the whole conversation again at the full price. Claude still receives the whole conversation, so it does not forget anything.

In the other versions, this was question 24 in Version B (correct answer: a) and question 41 in Version C (correct answer: e). The choices are in a different order in each version.

Background

The context window is the model’s working memory for one session. It holds Claude Code’s instructions, CLAUDE.md, your messages, Claude’s replies, every file Claude reads, and every command’s output. Every message you send makes Claude Code send all of this to the model again.

Current Claude models have large context windows (1 million tokens). But how full the window is still matters.

Context rot means that the model’s quality drops as the context window fills. The model may forget earlier instructions or decisions, or make more mistakes. Research has found that models tend to miss information in the middle of a long context more often than at its beginning or end. So a decision made halfway through a long session is at the highest risk.

The fix is to keep the used part of the window small:

Command What it does
/clear starts a new conversation with an empty context (CLAUDE.md still loads)
/compact summarizes the conversation so far to free space; /compact focus on ... tells it what to keep
/rewind goes back to an earlier point and drops the detour
/context shows what fills the window

When the window gets close to full, Claude Code also compacts automatically. Details that you mentioned only in the chat can be lost then. So put lasting decisions and rules in CLAUDE.md: it is loaded again after compaction and after /clear.

Do not confuse context rot with the prompt cache. An expired cache makes the next reply slower and more expensive. It does not change what Claude knows.

Question 15: Why LLMs work well with Markdown

Why do LLMs work so well with Markdown files, compared with Word or Excel files?

a. Markdown is a programming language that only LLMs can understand.

Wrong. Markdown is not a programming language, and it is not only for LLMs. It is a simple notation for formatting plain text, and any person can read it.

b. Markdown files store pictures and charts in a form that LLMs prefer.

Wrong. A Markdown file contains only text. It can link to an image, but the picture itself is a separate file. Pictures and charts are what make Word and Excel files harder for an LLM.

c. Markdown is plain text (just keyboard characters), so the LLM reads it directly. (correct answer)

Correct. A Markdown file is plain text: only characters that you can type on a keyboard. An LLM works with text, so it can read and write Markdown directly.

d. Markdown was invented by Anthropic for use with Claude and Claude Code.

Wrong. Anthropic did not invent Markdown. It is a general format that existed long before Claude; for example, README.md files on GitHub use it.

e. Markdown files are encrypted, so the LLM can read them without risk.

Wrong. Markdown files are not encrypted. They are plain text that anyone can open and read in any text editor. An encrypted file cannot be read without its key.

In the other versions, this was question 27 in Version B (correct answer: d) and question 33 in Version C (correct answer: d). The choices are in a different order in each version.

Background

Plain text is a file that contains only characters you can type on your keyboard: letters, digits, spaces and symbols. You can open it in any text editor and read it.

Markdown (files that end in .md) is plain text with a simple notation for formatting, called markup:

You type You get
# Heading a big heading (## to ###### for smaller ones)
- item a bullet point
1. item a numbered list item
*text* italics
**text** bold
[my site](https://example.com) a link
![photo](cat.png) a picture (a link to a separate image file)

The file stays readable even before it is formatted. A person who sees **bold** understands it.

An LLM works with text, as a sequence of tokens. A Markdown file is already text, so the LLM reads it directly. That is why Markdown is used so much in AI work: CLAUDE.md, AGENTS.md, skill files, and README.md files on GitHub are all Markdown.

A Word or Excel file is different. Besides the text, it can contain pictures, colors, fonts, charts and other formatting, stored in a file format that is not plain text. The LLM does not process these files directly.

So, when you write instructions or notes for an AI tool, use a plain-text format such as Markdown.

Question 16: How a model learns from wrong guesses

During training, a model reads a sentence and predicts the next word, but its prediction is wrong. What happens next?

a. A person adds a rule that gives the correct word for that sentence.

Wrong. Nobody writes rules for a language model. Writing rules is classic programming; in machine learning, the model learns from examples by itself.

b. The model saves the sentence, so it can look up the right word later.

Wrong. The model does not keep a copy of the text to look up later. What it learns is stored as small changes to its weights, not as saved sentences.

c. The model marks the sentence as wrong and skips it from then on.

Wrong. The model does not skip text after a wrong guess. It reads its training data many times, and each wrong guess is a chance to adjust itself.

d. The model adjusts itself slightly, so the right word is a bit more likely. (correct answer)

Correct. After a wrong prediction, the model changes its weights very slightly. The next time, the right word is a bit more likely.

In the other versions, this was question 22 in Version B (correct answer: b) and question 14 in Version C (correct answer: c). The choices are in a different order in each version.

Background

In classic programming, a person writes the rules. In machine learning, nobody writes the rules. The computer sees many examples and adjusts itself until it gets them right.

A large language model (LLM) is a machine-learning model that does one job: it predicts the next word (more exactly, the next token) in a piece of text. Inside the model are billions of numbers called weights (or parameters). The weights decide which next word the model thinks is likely.

Training works like this:

  1. The model reads some text and predicts the next word before it sees it.
  2. It compares its prediction with the real next word.
  3. If the prediction is wrong, it changes its weights very slightly, so the right word is a bit more likely next time.
  4. It repeats this for a huge amount of text.

The training data is enormous: web pages, books, articles and code. People often say that a model “reads the whole Internet”. This is not exactly true, but it is not far from the truth. The model reads this data many, many times.

Each change is very small. Many small changes, over trillions of tokens, give the model its knowledge of grammar, facts and style. This first stage is called pre-training. It takes months on thousands of special chips, so it costs a lot of money and electricity.

Two things that training does not do: it does not save the text so the model can look it up later, and it does not need a person to write a rule for each sentence.

Question 17: The model and the harness

Claude Code uses the Claude Opus 5.5 model. Which describes their roles correctly?

a. Claude Code is a model trained only for coding; Opus 5.5 is the subscription plan that it runs on.

Wrong. Claude Code is not a model; it is a program that uses a model. Opus 5.5 is not a subscription plan; it is a model. Plans are things such as Pro and Max.

b. Both are models; Claude Code is a smaller, faster version of Opus 5.5.

Wrong. Claude Code is not a model at all, so it is not a smaller version of Opus 5.5. It is the software that sends your requests to a model and runs tools for it.

c. Claude Code generates the next word; Opus 5.5 is the harness that runs commands on your computer.

Wrong. This choice swaps the two roles. Opus 5.5 is the model that generates text, and Claude Code is the harness that runs commands.

d. Opus 5.5 generates the next word; Claude Code is the harness that gives it tools to act. (correct answer)

Correct. Opus 5.5 is the model: it generates the next word. Claude Code is the harness: it gives the model tools and runs them. More exactly, a model generates the next token, which is a word or part of a word; the question says “word” to keep it simple.

In the other versions, this was question 25 in Version B (correct answer: a) and question 15 in Version C (correct answer: b). The choices are in a different order in each version.

Background

An AI coding tool has two parts that work together.

  • The model is the “brain”. It is an LLM that continuously generates the next word (more exactly, the next token) in a sequence. Claude’s models come in families such as Haiku, Sonnet, Opus and Fable, and each family has releases, for example Opus 5.5.
  • The harness is the software product around the model. It is written like classical software. It gives the model tools (read a file, edit a file, run a command), runs those tools, decides what the model sees (its context), and checks your permission settings. Claude Code is a harness.

The model never touches your computer directly. By itself, it can only produce text. When it needs to act, it asks for a tool, for example “read src/index.html”. Claude Code checks your permissions, runs the tool, and sends the result back to the model as text. The model reads the result and decides the next step. This repeated cycle is the agentic loop. The harness is what makes the system agentic: it lets the AI do things, not only write text.

A simple test: if it generates text, it is the model. If it runs commands, edits files, or manages the conversation, it is the harness.

One harness can use different models. In Claude Code, the /model command lets you choose a model (haiku, sonnet, opus or fable). The harness stays the same; only the model changes.

Question 18: Distilling an AI model

What does it mean to distill an AI model?

a. Replace the older part of a long conversation with a short summary.

Wrong. This describes compaction, which is what /compact does in Claude Code. It changes one conversation, not a model.

b. Train a new model on a large number of another model’s answers, so it imitates that model. (correct answer)

Correct. To distill a model, you collect many answers from that model and train a new model on them. The new model learns to imitate the first one.

c. Remove harmful or private material from the training data before training.

Wrong. This describes cleaning the training data. It does not copy anything from another model, so it is not distillation.

d. Make a model’s weights smaller and less exact, so it fits on a laptop.

Wrong. This describes making a model’s weights smaller and less exact (often called quantization). It changes one model’s size; it does not train a new model on another model’s answers.

In the other versions, this was question 1 in Version B (correct answer: a) and question 17 in Version C (correct answer: d). The choices are in a different order in each version.

Background

Distillation means training a model on another model’s answers, so that it learns to imitate that model. The steps are simple:

  1. Send a very large number of questions to a strong model.
  2. Save its answers.
  3. Train a new model on those questions and answers.

The new model does not get the first model’s weights. It only learns to give answers like the first model.

AI labs distill their own models, and that is allowed. Doing it to a competitor is different. A lab that opens fake accounts with a competitor to collect answers breaks the competitor’s terms of service.

In 2026, Anthropic accused Chinese AI labs of distillation attacks on Claude. In February, it accused three labs (DeepSeek, Moonshot and MiniMax) of using about 24,000 fraudulent accounts for more than 16 million exchanges with Claude. In September, it named seven China-based labs. These are accusations that the labs have not answered in public. Not everyone calls it theft: Nvidia’s CEO said “That’s called competition.”

A practical point for users: an unofficial reseller of cheap AI access may log or pass on what you type. Buy AI services through official channels.

Do not confuse distillation with these other ideas:

  • Compaction (/compact): a summary replaces the older part of a conversation.
  • Cleaning the training data: removing material before training.
  • Shrinking the weights: storing a model’s numbers less exactly, so the same model fits on smaller hardware.
