Question 28: /compact and /clear

What is the difference between /compact and /clear in Claude Code?

a. /compact keeps a summary of the conversation; /clear starts a new chat without one. (correct answer)

Correct. /compact replaces the conversation with a summary, so you can continue the same task with more free space. /clear erases the conversation and starts a new chat with no summary.

b. They do the same thing; /compact is just an older name for /clear.

Wrong. They do different things. /compact keeps a summary of the conversation; /clear keeps nothing from the conversation.

c. Both erase the whole conversation; /compact also removes CLAUDE.md from the context.

Wrong. /compact does not erase the whole conversation; it keeps a summary. Neither command removes CLAUDE.md: Claude Code loads it again after both.

d. /compact makes your project’s files smaller; /clear deletes them from your computer.

Wrong. Both commands change only the conversation in the context window. Neither command changes or deletes the files on your computer.

e. /clear keeps a summary of the conversation; /compact starts a new chat without one.

Wrong. This choice swaps the two commands. /compact is the one that keeps a summary; /clear starts a new chat without one.

In the other versions, this was question 16 in Version B (correct answer: a) and question 21 in Version C (correct answer: b). The choices are in a different order in each version.

Background

The context window is the model’s working memory: the maximum amount of text, counted in tokens, that it can consider at once. It holds the system prompt, your CLAUDE.md files, the skill descriptions, the conversation, files Claude read, and tool results.

A full context window causes problems:

  • Context rot: as the window fills, the model starts to forget things, especially from the middle of the conversation.
  • Cost: Claude Code sends the whole conversation again with every message, so a long conversation uses more tokens.

Claude Code has commands to keep the used part of the window small:

Command What it does Use it when
/compact Replaces the conversation with a summary You want to continue the same task
/compact pay special attention to ... The same, but tells the summary what to keep You know what matters next
/clear Erases the conversation and starts a new chat You switch to an unrelated task
/rewind Goes back to an earlier prompt in the conversation A path went wrong

After /clear, CLAUDE.md, the system prompt and the skill descriptions are still loaded. Only the conversation is gone. Claude Code also compacts by itself when the window is nearly full.

A summary can lose details. That is why rules that must last belong in CLAUDE.md, not only in the chat.

None of these commands changes your project’s files. They change only what is in the context window.

Question 29: Temperature and predictable answers

A bank wants its AI to stick closely to the most probable words, so that its answers are predictable. A novelist wants the AI to pick less likely words more often, so that its writing is surprising. Which setting controls this?

a. The effort level

Wrong. The effort level sets how much the model thinks before it answers. It does not control how often the model picks less likely words.

b. The number of tokens in the model’s vocabulary

Wrong. The vocabulary is the fixed set of tokens that a model uses. It does not decide how strictly the model picks from them.

c. The size of the context window

Wrong. The context window is how much text the model can consider at once. It does not change how the model picks the next word.

d. The number of parameters in the model

Wrong. The number of parameters measures the size of the model. It is fixed by training and is not a setting for how predictable the answers are.

e. The temperature (correct answer)

Correct. Temperature sets how strictly the model sticks to the most probable words. A low temperature suits the bank; a higher temperature suits the novelist.

In the other versions, this was question 36 in Version B (correct answer: c) and question 31 in Version C (correct answer: d). The choices are in a different order in each version.

Background

For each next word (more exactly, each next token), a model calculates a probability distribution: a probability for every token it knows. For “The boy went to the ___“,”store” and “school” have high probabilities, and “purple” has a very low one. The software then picks one token from this distribution. It usually picks a likely token, but not always the most likely one. With two dice, 7 is the most likely total, but other totals also happen.

Temperature is the setting that controls how this pick is made. It is typically a number between 0 and 1.

  • Low temperature (near 0): the model almost always picks the most probable token. Answers are more predictable. At 0, it always picks the most probable token, although the output is still not guaranteed to be identical every time.
  • Higher temperature (near 1): the model picks according to the learned probabilities, so less likely tokens are picked more often. Answers are more varied and surprising, but also more likely to go off track.

Do not confuse temperature with other settings and sizes:

Term What it is
Effort How much the model thinks before it answers
Context window How much text the model can consider at once
Vocabulary The set of tokens the model uses
Parameters The model’s weights; their number measures the model’s size

Chat apps choose the temperature for you. Many developer APIs let you set it, but some newer models, including Anthropic’s newest Claude models, no longer allow you to change it.

Question 30: Where to put a standing rule

You want Claude Code to follow a rule every time it works on your project: “Run the tests before you say that a task is done.” Where should this rule go?

a. In README.md

Wrong. README.md describes the repository for people, and GitHub shows it on the repository’s home page. Claude Code does not load it automatically as a set of rules.

b. In a skill

Wrong. Claude Code loads a skill’s full instructions only when it decides that they are useful, or when you type the skill’s slash command. A rule that must apply every time could be missed.

c. In CLAUDE.md (correct answer)

Correct. Claude Code loads CLAUDE.md automatically at the start of every session in that folder. Claude sees the rule every time it works on the project.

d. In the system prompt

Wrong. The system prompt is written by the maker of the tool, not by you. You cannot put your own project’s rules there.

e. In an MCP server

Wrong. An MCP server connects Claude to an outside service and gives it new tools. It is not a place for rules about how Claude works.

In the other versions, this was question 41 in Version B (correct answer: d) and question 9 in Version C (correct answer: b). The choices are in a different order in each version.

Background

Each Claude Code session starts with a fresh context window, Claude’s working memory. Claude does not remember earlier sessions by itself. CLAUDE.md is a plain-text Markdown file that gives Claude standing instructions: how to run the project, the team’s rules, mistakes to avoid.

How CLAUDE.md works:

  • Claude Code puts CLAUDE.md into the context automatically, at the start of every session in that folder.
  • You can have different CLAUDE.md files in different folders. A project’s CLAUDE.md is usually committed to Git, so the whole team shares it.
  • After /clear or /compact, CLAUDE.md is still loaded.
  • AGENTS.md does the same job. It became the standard file name for all AI coding tools, and Claude Code also recognizes it.

Compare CLAUDE.md with a skill. Only a skill’s description is always in the context; its full instructions load only when Claude decides they are useful. So:

Kind of instruction Where it goes
A rule for all work on the project (“run the tests before you say a task is done”) CLAUDE.md
A procedure for one kind of task (“make the weekly sales report”) A skill

Keep CLAUDE.md short. Everything in it uses context space in every session.

One more fact: CLAUDE.md is guidance, not a guarantee. Claude reads it and tries to follow it, but nothing forces it to. If something must never happen, use a permission rule or a hook instead.

Question 31: What a static website can do

Which of these could be built as a static website (only HTML, CSS and JavaScript files)?

a. A site where visitors post comments that later visitors can read.

Wrong. The site must save each comment and show it to later visitors. That needs a database and server-side code, and a static website has neither.

b. A restaurant’s site that shows its menu, hours and address, the same for every visitor. (correct answer)

Correct. The menu, hours and address are the same for every visitor. Only the owner changes them, by editing the files, so HTML, CSS and JavaScript files are enough.

c. A site where visitors create accounts and log in to see their saved favorites.

Wrong. Accounts and logins need a way to know who is asking, and saved favorites need data storage for each user. A static website has no users, no logins and no data storage.

d. A site that recommends products based on what each visitor bought before.

Wrong. Recommendations based on past purchases need a stored record of what each visitor bought. A static website cannot store data or tell one visitor from another.

In the other versions, this was question 13 in Version B (correct answer: a) and question 43 in Version C (correct answer: a). The choices are in a different order in each version.

Background

A static website is a set of files that were prepared ahead of time: HTML, CSS and JavaScript. The web server sends the same files to every visitor. You can even open a static website on your own computer by double-clicking its main .html file. The olympics demo site from class and this book are static websites.

On a static website:

  • every visitor sees the same information;
  • only the owner changes what the site shows, by changing the files;
  • there are no users and no logins;
  • nothing that a visitor does is stored.

A dynamic website runs code on the server for each request. That code builds a page for that user at that moment, for example your order history or your bank balance. A dynamic website needs three things that a static website does not have:

  • server-side code (code that runs on the server, not in the browser);
  • a database (a program that stores data and gives it back when asked);
  • a way to know who is asking (logging in).

A static website can still be interactive. JavaScript can open menus or show photos when you click, because this happens in your browser and nothing is saved.

To decide if a site can be static, ask two questions. Does the site need to remember something that a visitor did? Does it show different content to different visitors? If the answer to both is no, a static website is enough.

Question 32: Agentic AI tools vs. coding tools

Which task is the best fit for an agentic AI tool, such as Muse, and not for Claude Code?

a. Write a program that adds two 100-digit numbers exactly.

Wrong. Exact arithmetic with big numbers is a programming job. A coding tool such as Claude Code can write and run a short program that adds the numbers exactly.

b. Turn a folder of code into a git repo and put it on GitHub.

Wrong. Creating a git repo and uploading it to GitHub is software-development work. In class, Claude Code did exactly this for the demo website.

c. Find the bug that makes your app crash when a user logs in.

Wrong. Finding a bug in an app’s code is a core job of a coding tool. Claude Code can read the code, run it and change it.

d. Each morning, answer meeting requests in your email and reorder office supplies. (correct answer)

Correct. Answering email and ordering supplies are everyday tasks, not software work. Agentic AI tools focus on getting such things done, and they can do almost anything online that a person can.

e. Build a website for your club out of HTML, CSS and JavaScript files.

Wrong. Building a website from HTML, CSS and JavaScript files is software development. In class, Claude Code built a static website in this way.

In the other versions, this was question 14 in Version B (correct answer: a) and question 4 in Version C (correct answer: b). The choices are in a different order in each version.

Background

Generative AI makes content: a chat tool writes text, and other tools make images, music or video. Agentic AI does things with tools. It can change files on your computer, run programs, browse the web, search for information and place orders.

The course sorts AI tools into three groups:

Group Main focus Examples
Chat tools Conversation in a web page or app ChatGPT, claude.ai, Grok
Coding tools Building software Claude Code, Codex, Cursor
Agentic AI tools Getting everyday things done Open Claw, Hermes, Muse (Meta), Dots (OpenAI), Grokbot (xAI)

Coding tools are agentic too. Claude Code reads and edits files and runs commands on your computer. But its focus is software: writing programs, fixing bugs, using git and GitHub, and building websites.

Agentic AI tools focus on everyday tasks. They can do almost anything online that a person can, such as answering email, booking meetings or ordering products. They can also change files and run programs.

The groups change over time. For example, the claude.ai web interface now has some Claude Code features. To pick the best tool, look at the goal of the task. If the result is software, a coding tool is the best fit. If the result is an everyday job done for you, an agentic AI tool is the best fit.

Question 33: Bash on Mac, Linux and Windows

A Mac user, a Linux user and a Windows user all want to use the Bash commands that we learned in class. Which is correct?

a. Windows already has Bash built in; it is called CMD.

Wrong. CMD is the original command-line language of Windows, not Bash. It can do the same jobs as Bash, but with different commands.

b. The Mac and Linux users have Bash; the Windows user can install it, for example with Git Bash. (correct answer)

Correct. Bash is available on Mac and Linux. Windows does not include it, but you can install it for free, for example with Git Bash, which we used in class.

c. Only the Linux user has Bash; Macs and Windows use PowerShell instead.

Wrong. Macs have Bash too, so a Mac user can use the same commands as a Linux user. PowerShell comes with Windows; the Mac comes with Bash.

d. None of them has Bash until they install it, because no operating system includes it.

Wrong. Mac and Linux already include Bash. Only the Windows user must install it.

In the other versions, this was question 3 in Version B (correct answer: d) and question 11 in Version C (correct answer: d). The choices are in a different order in each version.

Background

A CLI (command-line interface) lets you control the computer by typing commands in a terminal program. The program that reads and runs your commands is the shell. Each shell has its own command language.

Bash is probably the most popular command language. The commands we learned in class, such as pwd, ls, cd and mv, are Bash commands.

Computer Bash? Other command languages
Linux Included
Mac Included zsh, the Mac’s default shell; for the class commands it works the same as Bash
Windows Not included; install it, for example with Git Bash (free) or WSL2 PowerShell (newer, more powerful) and CMD (the original, simpler)

Bash, PowerShell and CMD can all do the same jobs, such as moving files or making folders. They use different commands to do them. So a Bash command that you learned in class does not always work in PowerShell or CMD.

In this course, Windows users installed Git Bash. After that, all three users can type the same Bash commands and get the same results. (We did not cover WSL2.)

Question 34: GitHub’s role in team projects

Three students work together on the same project. What role does GitHub play?

a. Each student clones the repo and shares changes with the others through it. (correct answer)

Correct. GitHub keeps a copy of the repo online. Each student clones it to download a copy, uploads their own changes to GitHub, and downloads the changes that the others made.

b. GitHub emails each student a new copy of the code whenever someone saves a file.

Wrong. GitHub does not email copies of code, and saving a file does not send anything. Each student downloads the others’ changes from GitHub when they choose.

c. Only the repo’s owner can download it; the others email their changes to the owner.

Wrong. Other people can clone a repo too: anyone can clone a public repo, and the people that the owner allows can clone a private repo. Team members share changes through GitHub, not by email.

d. GitHub replaces git, so the students don’t need git on their computers.

Wrong. GitHub is a website for git repos; it does not replace git. Each student still uses git on their own computer to record changes and to send them to GitHub.

In the other versions, this was question 4 in Version B (correct answer: c) and question 42 in Version C (correct answer: d). The choices are in a different order in each version.

Background

Git is a program that runs on your computer. It records versions of the files in a project folder. A folder that git tracks is a repository (repo). Git works offline and needs no account.

GitHub is a website that stores copies of git repos on the Internet. It is not the same as git. You need an account and an Internet connection to use it.

How a team works with GitHub:

  1. One person uploads the repo to GitHub.
  2. Each team member clones the repo. Cloning downloads a copy of the repo, with its whole history, to your computer. The copy remembers where it came from.
  3. Each person changes files and records the changes with git on their own computer.
  4. Each person uploads (pushes) their changes to GitHub and downloads (pulls) the changes that the others made.

To coordinate the work of many people on one repo, you need more git ideas, which the course covers later.

A GitHub repo can be public (anyone can see it) or private (only you and the people you allow can see it). GitHub is also useful for one person: you get an online copy of your work that you can use from anywhere, and you can show your work to others.

Question 35: Vercel’s job in the task app

What is Vercel’s job in the task app’s architecture?

a. It sends each new task to an AI model and gets back a label.

Wrong. This is the job of the OpenAI API. An Edge Function on Supabase sends the new task to OpenAI and gets back the label.

b. It checks users’ passwords and handles “Sign in with Google”.

Wrong. Supabase does authentication, including “Sign in with Google” (with Google’s sign-in service). Vercel does not check passwords.

c. It stores the app’s data, such as each user’s tasks and profile.

Wrong. Supabase stores the app’s data, in its PostgreSQL database.

d. It stores the app’s code and keeps the history of every change.

Wrong. GitHub stores the code and the history of every change; your copy is a fork. Vercel imports the code from GitHub, but it is not where the code and its history are kept.

e. It hosts the website online, so anyone can open the app at a public address. (correct answer)

Correct. Once the app is online, Vercel is the web server. It imports the code from GitHub, builds the app and hosts it at a public address, so anyone can open it.

In the other versions, this was question 30 in Version B (correct answer: c) and question 19 in Version C (correct answer: e). The choices are in a different order in each version.

Background

A web server is a program that sends a website’s pages to browsers. A host is a company whose computers run your website on the Internet.

The task app runs in two places at different times:

  • While you develop, the web server is a development server on your own computer. Its address is localhost:3000, which means “the program on this computer that listens on port 3000”. Nobody else can open it.
  • After you deploy, the same app runs on Vercel at a public address. Anyone with the address can open it.

In both places, the back end is the same Supabase project.

Deploying means putting the app online. With Vercel it works like this:

  1. Vercel imports your repository (your fork) from GitHub.
  2. Vercel builds the app and hosts it at a public address.
  3. From then on, every push to your fork makes Vercel deploy the new version automatically.

You give Vercel only the Supabase URL and the publishable key. You give it no secret keys, because the secrets stay on Supabase.

Each part of the tech stack has one job. Vercel hosts the website. Supabase gives the database, logins, image storage and Edge Functions. GitHub stores the code. Google, OpenAI and Stripe do sign-in, AI labels and payments.

Question 36: Model size and capability

Model X has a few billion parameters. Model Y has over a trillion. Which is most likely true?

a. Both are equally capable, because parameters only affect the speed.

Wrong. Parameters are the numbers inside the model that training adjusts. They hold what the model learned, so they affect what the model can do, not only its speed.

b. X is likely more capable, because fewer parameters cause less confusion.

Wrong. More parameters do not cause confusion. In general, a bigger model can learn more, and the most capable models are among the biggest.

c. Y can serve more users at once, because parameters count users.

Wrong. Parameters do not count users. They are the weights inside the model’s neural network.

d. X is likely more capable, because smaller models are trained for longer.

Wrong. Small models are not usually trained for longer. The more capable models are often trained with more data and for longer, and they are often bigger too.

e. Y is likely more capable, because it is a much bigger model. (correct answer)

Correct. More capable models are often bigger. Frontier models have hundreds of billions to trillions of parameters, and a model with a few billion parameters is a small model.

In the other versions, this was question 15 in Version B (correct answer: c) and question 35 in Version C (correct answer: c). The choices are in a different order in each version.

Background

Almost all modern AI uses an artificial neural network. It is made of many simple units (“neurons”) in layers. Each connection between units has a number, called a weight or parameter. It sets how strongly one unit affects the next.

Nobody sets these numbers by hand. During training, the model sees an example, compares its answer with the correct one, and changes every parameter a very small amount toward the better answer. This repeats billions of times. What the model learns is stored in its parameters.

Models are usually described by how many parameters they have:

Kind of model Parameters Runs on
Small model A few billion A laptop
Frontier model (one of the most capable models) Hundreds of billions to trillions Very expensive hardware in data centers

More capable models are often:

  • bigger (more parameters);
  • trained with more data;
  • trained for longer.

These are trends, not rules. That is why the question asks what is most likely true. Bigger models also cost much more to train and to run. A small model that runs on your own computer is slower and less capable, but your data does not go to another company.
