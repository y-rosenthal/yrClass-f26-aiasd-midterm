Question 37: The jobs of HTML, CSS and JavaScript

A web page has (1) headings, paragraphs and a bullet list; (2) its own colors and fonts; and (3) a button that, when clicked, shows extra details. Which language is mainly responsible for each?

a. (1) CSS; (2) HTML; (3) JavaScript

Wrong. This swaps HTML and CSS. HTML gives the text and structure, such as headings and lists, and CSS gives the colors and fonts.

b. (1) HTML; (2) CSS; (3) JavaScript (correct answer)

Correct. HTML gives the content and structure, CSS gives the look, and JavaScript adds behavior, such as what happens on a click. These are the basic roles, not strict rules: HTML alone can show extra details on a click, with the <details> and <summary> elements. But the language that is mainly responsible for click behavior is JavaScript, and no other choice matches the first two parts.

c. (1) HTML; (2) JavaScript; (3) CSS

Wrong. This swaps CSS and JavaScript. CSS sets the colors and fonts, and JavaScript controls what happens when you click a button.

d. (1) JavaScript; (2) CSS; (3) HTML

Wrong. HTML, not JavaScript, gives the headings, paragraphs and lists. JavaScript, not HTML, is mainly responsible for what happens on a click.

In the other versions, this was question 20 in Version B (correct answer: a) and question 30 in Version C (correct answer: c). The choices are in a different order in each version.

Background

A browser shows a web page from code in three languages. Each language has a main job:

Language Main job Examples
HTML (HyperText Markup Language) Content and structure Headings, paragraphs, bullet lists, tables, links, buttons
CSS (Cascading Style Sheets) Look and feel Colors, fonts, spacing, layout
JavaScript (JS) Interactivity (behavior) What happens when you click or hover; changing the page without reloading it

HTML is written with tags, such as <h1> and </h1>. CSS is written as rules that say how things look. JavaScript looks like a usual programming language, with functions, if/else and loops.

You can keep each language in its own file (.html, .css, .js), or you can put all three in one .html file.

These jobs are the basic idea, not strict rules. HTML can control some of the look, and JavaScript can create text and change the HTML and CSS. HTML also has a few elements with built-in behavior: for example, <details> and <summary> show or hide extra text on a click. When a question asks which language is mainly responsible, use the main jobs in the table.

Question 38: How an LLM picks the next word

An LLM is completing “The boy went to the ___“. Suppose”store” is the most probable next word. Which is correct?

a. The model always picks “store”, because it is the most probable word.

Wrong. This is true only when the temperature is set to 0; then the model (almost) always picks the most probable word. With normal settings, the model picks from a probability distribution, so the most probable word is not always the one that is picked.

b. “Store” is the most likely pick, but a less likely word, such as “beach”, may be picked instead. (correct answer)

Correct. The model gives every possible word a probability and then picks from that distribution. “Store” has the highest chance, but a less likely word such as “beach” is sometimes picked, in the same way that 7 is the most likely roll of two dice but other rolls also happen.

c. Only words that followed this exact sentence in the training data can be picked.

Wrong. The model does not copy sentences from its training data. It gives a probability to every word that it knows, so even an unusual word such as “purple” (“the purple room”) can be picked.

d. Adding earlier text, such as a story about clowns, doesn’t change the probabilities.

Wrong. Earlier text changes the probabilities. After a story about clowns, “circus” can become the most probable next word.

In the other versions, this was question 17 in Version B (correct answer: b) and question 16 in Version C (correct answer: a). The choices are in a different order in each version.

Background

A large language model (LLM) does one basic thing: it reads text and predicts what comes next. It does not work with whole words but with tokens, small pieces of text. To make it simple, this explanation says “word”.

For “The boy went to the ___“, the model gives a probability to every word that it knows. The probabilities add up to 1. Most words get a very small probability, but some get more, for example:

  • “store”: highest
  • “school”: lower
  • “beach”: lower still
  • “purple”: very low, but not zero (“the purple room”)

This list of words and probabilities is a probability distribution. The software then samples from it: it usually picks a likely word, but not always the most likely one. That is why the same question asked twice can get two different answers. An AI model is non-deterministic: the same input does not always give the same output.

Temperature is a setting that controls how random the pick is. At temperature 0, the model (almost) always picks the most probable word. At temperature 1, it picks according to the learned probabilities. Chat apps choose this setting for you.

The context (the text before the blank) changes the probabilities. After a story about clowns, “circus” can become the most probable word.

Question 39: The /rewind command in Claude Code

What is the /rewind command in Claude Code used for?

a. Switching back to the model that you used before.

Wrong. This describes /model, which chooses the model. /rewind does not change the model.

b. Summarizing the older part of the conversation to save space.

Wrong. This describes /compact, which summarizes the conversation so far to free up space in the context window.

c. Going back to an earlier prompt in this conversation. (correct answer)

Correct. /rewind lists your prompts from the current conversation and lets you go back to one of them. The part after that point leaves the context, which helps avoid context rot and saves tokens on later messages.

d. Reloading CLAUDE.md after you have edited it.

Wrong. /rewind does not reload CLAUDE.md. It goes back to an earlier prompt in the current conversation.

e. Showing how much of the context window you have used so far.

Wrong. /rewind does not show how much of the context window you have used. /context shows what fills the window, and you can use /statusline to add the % used to the status line.

In the other versions, this was question 6 in Version B (correct answer: e) and question 39 in Version C (correct answer: e). The choices are in a different order in each version.

Background

The context window is the maximum amount of text, measured in tokens, that the model can consider at once. In Claude Code it holds the system prompt, CLAUDE.md, the conversation so far, files that Claude read, and tool results. Claude Code sends the whole conversation again with every message, so a long conversation uses more tokens on each message.

Context rot means the model starts to forget things as the context window fills up, more from the middle of the conversation. To prevent it, keep the used part of the context window small. Three commands help:

Command What it does Use it when
/clear Erases the conversation and starts a new one (CLAUDE.md still loads) You switch to an unrelated task
/compact Summarizes the conversation so far to free up space You are at a break in a long task
/rewind Lists your prompts and goes back to one of them (also Esc twice on an empty prompt) A path went wrong after a certain prompt

For example, you spend twenty minutes on an approach that does not work. With /rewind, you go back to the prompt before the failed approach. The failed part no longer takes up the context window, and you do not pay tokens for it on every later message. /rewind also goes back to a point that the prompt cache already holds, so it is cheap.

Type / in Claude Code to see all the slash commands.

Question 40: The training (knowledge) cutoff date

What is the significance of a model’s training cutoff date?

a. When training starts; after it, the model keeps learning from each chat.

Wrong. The cutoff is the date the training data ends, not the date training starts. The model does not learn from your chats: its weights do not change while you chat.

b. The date the model stops working; a new model must replace it.

Wrong. The model keeps working after its cutoff date. It only lacks built-in knowledge of what happened after that date.

c. Its built-in knowledge ends there; web search can fill the gap. (correct answer)

Correct. What the model learned is stored in its weights, and that knowledge ends at the date the training data ends. Apps add newer facts with web search or with documents that you paste in.

d. The last date the model can search the web.

Wrong. This reverses the idea. The cutoff limits the model’s built-in knowledge, and web search is how apps work around the cutoff.

In the other versions, this was question 10 in Version B (correct answer: b) and question 2 in Version C (correct answer: c). The choices are in a different order in each version.

Background

An LLM has two kinds of “memory”.

Long-term memory is what the model learned in training. It is stored in the model’s weights (the numbers inside the model). It ends at the knowledge cutoff (also called the training cutoff): the date when the training data ends. The weights do not change while you chat, so the model does not learn from your conversations.

Working memory is the context window: the text that the model can consider for the current request. This includes the system prompt, the conversation so far, files and tool results.

Because of the cutoff:

  • the model knows little about events after the cutoff;
  • it may confidently describe an old version of a tool that changes fast, including Claude Code itself.

Apps work around the cutoff by putting newer information into the context window:

  • web search: the app searches the web and adds the results to the context;
  • documents: you paste the current documentation or a changelog into the chat.

A model keeps working after its cutoff. A newer model has a later cutoff because it was trained on newer data.

Question 41: Choosing a Claude model for a job

In Claude Code you have two jobs: renaming 50 files, and redesigning a complicated app. Which model choice makes the most sense?

a. Haiku for both, because all Claude models are equally smart.

Wrong. Claude models are not equally smart. Haiku is the least capable family; it is fine for simple work but not for a complicated redesign.

b. Haiku for the renaming; Opus or Fable for the redesign. (correct answer)

Correct. Renaming files is simple work, so Haiku is enough and costs less. A complicated redesign needs a more capable model, such as Opus or Fable.

c. Fable for the renaming; Haiku for the redesign.

Wrong. This is backwards. Fable costs much more to run than simple renaming needs, and Haiku is the least capable model for a complicated redesign.

d. Mythos for both, because it is the most capable model.

Wrong. Mythos was never released to the public, so you cannot use it for these jobs. Anthropic uses it for internal security testing and gives it only to select customers.

e. Fable for both, because better models cost the same to run.

Wrong. Better models are smarter but cost much more to run. Using Fable for simple renaming uses much more of your plan for no benefit.

In the other versions, this was question 21 in Version B (correct answer: e) and question 18 in Version C (correct answer: d). The choices are in a different order in each version.

Background

Anthropic’s Claude models come in families. From least capable to most capable:

Family Good for
Haiku Simple, quick tasks; the fastest and cheapest
Sonnet Basic, everyday work
Opus More complicated work
Fable The hardest tasks; the best model released to consumers
Mythos Never released to the public; used for security testing inside Anthropic and by select customers

Each family has releases with version numbers, such as Opus 4.0, Opus 4.1 and later versions.

The trade-off is simple: better models are smarter, but they cost much more to run. On a subscription, a more capable model uses up your usage limits faster. So match the model to the job:

  • a simple, repeated job (renaming files, small edits): a less capable model, such as Haiku;
  • a complicated job (designing or redesigning an app): a more capable model, such as Opus or Fable.

In Claude Code, you choose the model with the /model command, for example /model haiku or /model fable. You can also choose the effort with /effort: how hard the model thinks before it answers.

Question 42: How git helps with broken code

Your project’s code worked last week, but today it is broken. How can git help?

a. It stores older versions of your code, so you can go back to the version that worked. (correct answer)

Correct. Each commit records the state of all the project’s files at that moment. You can see what changed since the version that worked, and you can go back to that version.

b. It locks the code in the hidden .git folder, so that nobody can change it.

Wrong. The .git folder holds git’s record of every version. It does not lock your files; you edit them normally.

c. It uploads your code to a website, so that other people can test it.

Wrong. This describes GitHub, a website that stores copies of git repos online. Git itself is a program that runs on your computer and works offline.

d. It finds and fixes the bug automatically.

Wrong. Git does not find or fix bugs. It records versions, so you can compare them and go back to an earlier one.

In the other versions, this was question 28 in Version B (correct answer: c) and question 25 in Version C (correct answer: b). The choices are in a different order in each version.

Background

Git is a tool for managing changes to files over time, mostly code files. It works with any text files.

With git, you take a snapshot of your project whenever you reach a good point, for example “the login page works”. In git, a snapshot is a commit. Each commit records:

  • the state of all the project’s files at that moment;
  • a short message that describes the change;
  • the author and the date;
  • a unique ID, such as 4293e1d.

The list of all commits is the project’s history. With the history you can:

  • see the state of the files in an earlier version;
  • see the differences between two versions, line by line;
  • go back to an earlier version of one file or of the whole project.

A repository (repo) is a project folder whose history git keeps. Git stores the history in a hidden folder named .git at the top of the repo. If you delete .git, your files stay, but the history is gone.

So if your code worked last week, and you made a commit then, git can show you what changed since then and bring back the working version. This is even more important when an AI coding agent changes many files for you: commit before you let it work.

Question 43: CLI vs. GUI

You move a file to another folder by typing a command in a terminal. Your friend does the same by dragging the file’s icon. Which is correct?

a. You used a CLI, which needs the Internet; your friend used a GUI, which works offline.

Wrong. Neither a CLI nor a GUI needs the Internet in general; both control your own computer. Some CLI tools need the Internet, such as Claude Code, which talks to a model online, but a command that moves a file works offline.

b. You used a GUI; your friend used a CLI. Both can do the same job.

Wrong. This swaps the two terms. Typing a command in a terminal is using a CLI, and dragging an icon is using a GUI.

c. You used a CLI; your friend used a GUI. Both can do the same job. (correct answer)

Correct. Typing a command in a terminal is using a CLI (command-line interface), and dragging an icon is using a GUI (graphical user interface). Both can move the file.

d. You used a CLI, which can only manage files; your friend used a GUI, which can do anything.

Wrong. A CLI can control all parts of the computer, not only files. Most jobs can be done with either a CLI or a GUI.

In the other versions, this was question 31 in Version B (correct answer: c) and question 10 in Version C (correct answer: a). The choices are in a different order in each version.

Background

You can control a computer in two ways.

  • A GUI (graphical user interface) is the usual way. You use windows, icons and menus, and you click and drag with a mouse or trackpad.
  • A CLI (command-line interface) is a text conversation with the computer. You type a command in a terminal program and press Enter, and the computer answers with text.

For example, this Bash command moves the file todo.txt from Joe’s finance folder to his personal folder:

mv /Users/joe/finance/todo.txt /Users/joe/personal

  • mv is the “move” command.
  • /Users/joe/finance/todo.txt is the full path to the file.
  • /Users/joe/personal is the folder that the file moves to.

Dragging the file’s icon from one folder to the other in Finder or File Explorer does the same job with a GUI.

A CLI can control all parts of the computer, not only files. Neither way needs the Internet, unless the program that you use works online.

AI coding tools such as Claude Code mostly use the CLI. Commands are text, which an LLM knows very well. Controlling a GUI is now possible for AI, but it usually takes more tokens than doing the same job with commands.

Question 44: AI safety and model vocabulary

Matching was not graded on this exam: everyone was told to skip it. It is explained here so that you can learn the material.

Match each term with its meaning. Two meanings are not used. (10 points)

Item Correct match Meaning
1. Jailbreak A A prompt designed to get around a model’s safety rules
2. Misalignment G AI that pursues goals that conflict with what people intend
3. Token C A small piece of text, often part of a word; models read and write text in these units
4. Frontier model E One of the most capable general-purpose models, matching or beating today’s best
5. Context window B The maximum amount of text that the model can consider at once
(not used) D The date when the data that a model was trained on ends
(not used) F Instructions hidden in content that the AI reads, such as a web page or an email

1. Jailbreak → A

A jailbreak is a prompt that tries to get a model to do or say what its safety rules forbid. The person who types the prompt is the attacker.

2. Misalignment → G

Alignment means an AI uses its abilities the way people intend. Misalignment means the AI pursues goals that conflict with those intentions.

3. Token → C

A tokenizer splits text into tokens before the model sees it. A common word is often one token, and a longer or rarer word is split into pieces.

4. Frontier model → E

A frontier model is one of the most capable general-purpose models available, matching or beating today’s best.

5. Context window → B

The context window is the maximum amount of text, measured in tokens, that the model can consider at once.

D. The date when the data that a model was trained on ends (not used)

This meaning defines the knowledge cutoff (training cutoff): the date when the model’s training data ends.

F. Instructions hidden in content that the AI reads, such as a web page or an email (not used)

This meaning defines prompt injection. The attacker hides instructions in content that the AI reads, and the user is the victim, not the attacker.

In the other versions, this was question 45 in Version B and question 45 in Version C. The items and meanings are in a different order there, so the letters are different.

Background

These terms come from two areas: how LLMs work, and AI safety.

How LLMs work

  • A token is a small piece of text that occurs often in the training data. Some words are one token; others, such as “dictionary”, may be several (dict-ion-ary). A model reads and writes tokens, not letters or whole words.
  • The context window is the model’s working memory: the maximum amount of text, in tokens, that it can consider at once. It holds the system prompt, the conversation, files and tool results.
  • The knowledge cutoff is the date when the training data ends. The model knows little about later events.
  • A frontier model is one of the most capable general-purpose models of the moment.

AI safety

  • Alignment means an AI uses its abilities the way people intend. Misalignment means it pursues goals that conflict with what people intend. For example, an AI told to make money on the stock market might cause harm that nobody wanted, only to reach its goal.
  • A jailbreak is a prompt designed to get around a model’s safety rules, for example “I am writing a play about criminals…”. The person who types is the attacker.
  • Prompt injection is different: an attacker hides instructions in content that the AI reads, such as a web page or an email. The user is the victim. This is a large risk for agents, because they can take real actions.

Question 45: The task app’s tech stack

Matching was not graded on this exam: everyone was told to skip it. It is explained here so that you can learn the material.

Match each part of the task app’s tech stack with its job. One job is not used. (10 points)

Item Correct match Meaning
1. OpenAI API B Picks a label for each new task
2. Stripe C Handles subscription payments
3. Supabase A The ready-made back end: database, logins, image storage, Edge Functions
4. GitHub E Stores the app’s code; your copy is a fork
5. Google F Lets users sign in with an account they already have
(not used) D Writes the app’s code automatically from your description

1. OpenAI API → B

When a user creates a task, an Edge Function sends the task’s title and description to the OpenAI API, which returns one label.

2. Stripe → C

Stripe handles the payments for the Premium plan, with its checkout page and its customer portal.

3. Supabase → A

Supabase is the ready-made back end. It gives the app a PostgreSQL database, logins, storage for images and Edge Functions.

4. GitHub → E

GitHub stores the app’s code. Your copy is a fork: your own copy of the course’s repository, in your GitHub account.

5. Google → F

“Sign in with Google” lets users sign in with a Google account that they already have. Supabase does the login, and Google confirms who the user is.

D. Writes the app’s code automatically from your description (not used)

No part of the tech stack writes the app’s code. The code was already written (it comes from a tutorial video); this meaning describes an AI coding tool, such as Claude Code.

In the other versions, this was question 44 in Version B and question 44 in Version C. The items and meanings are in a different order there, so the letters are different.

Background

A tech stack is the set of technologies that an app is built from, together with where each part runs. The task app uses the computers of many companies:

Part Its job
Next.js The framework that the app is written in; it makes the front end (in the browser) and a part that runs on the web server
Supabase The ready-made back end: PostgreSQL database, logins, image storage, Edge Functions
Google “Sign in with Google”
OpenAI API Picks a label for each new task
Stripe Subscription payments
GitHub Stores the code; your copy is a fork
Vercel Hosts the website online (the web server)

An Edge Function is a small program that runs on Supabase’s servers. The app’s Edge Functions talk to OpenAI and Stripe, because those requests need secret keys, and anything in the browser can be read by anyone.

Why so many companies? Each company specializes in one hard job, such as logins, payments or AI. Instead of building these yourself, you use their service. The app connects to each service with web addresses and keys. The trade-off is that you must manage many accounts, keys and settings.

The app’s code was already written. The setup work was to create the accounts and to connect the services.
